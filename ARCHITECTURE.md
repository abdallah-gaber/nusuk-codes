# Architecture

Static Vite SPA. Visitor fetches `/data/manifest.json`, then the content-addressed snapshot. No Firestore reads/writes, Functions or realtime listeners. Production builds include owner-enabled Vercel Web Analytics for page views; development builds do not mount it. No custom interaction events or local history are included in analytics. Browsing, search and copying use loaded data. Open navigates to an official Nusuk URL. Tailwind is compiled with Vite; CSS decorations and system Arabic fonts avoid external font/image requests.

Manifest carries schema, canonical `nov-2026` season (CSV `2026-11`), generation date, count, SHA-256, snapshot URL, readOnly/submissionsEnabled, maintenance and candidatePreview flags. Fetches timeout after 10 seconds. The client validates the manifest, exact count, duplicate codes, status, season, source domains and payload checksum before use. The provisional regex is a syntax check only.

The last-good raw snapshot and manifest are cached in localStorage, then revalidated on fallback. Storage failures never block browsing. History is stored independently at `(season, exact-case code)` with a per-browser random seed for a deterministic Fisher–Yates shuffle. Seen means displayed, including the current card; tried/skipped are explicit local annotations. The optional `current` field in the existing v1 history stores the exact current code, or null for exhaustion, alongside counters in a single storage write. Refresh restores it without another view. Older records without this field recover their latest available seen code, then persist the cursor. If none remains, the first available unseen display is counted once. Imports merge arrays while retaining the local cursor. Copy/Open never advance. Next has no daily limit. Exhaustion does not restart without confirmed reset. Undo restores the previous card and history. Cross-tab updates follow last-writer-wins; simultaneous clicks in different tabs can lose a local annotation. No device synchronization; export/import unions exact-case arrays without replacing existing history.

Only data assets are cached; this is not a PWA. Offline fallback works when the application shell is already available (open tab or browser HTTP cache), not a guaranteed cold offline launch. A network failure never clears history. A valid cached snapshot may be old; the UI labels fallback and age. `readOnly` is operational metadata: Phase 1 always disables submissions regardless of manifest flags.

Full dataset provenance lives outside `public/`. The public JSON exposes source domains and observation date only. Candidate status remains unverified. Publication requires owner-approved community display under the documented policy. It does not establish independent source/season verification or redemption. The manifest retains `candidatePreview: true` for unverified community candidates.

Vercel header configuration: manifest max-age 300/s-maxage 600; hash snapshots max-age one year immutable. Deploy snapshot and manifest together; retain the prior deployment for rollback. Publication validation enforces 4,000,000 raw bytes and 250,000 gzip bytes. The checked-in manifest identifies the current snapshot and count.

## Phase 2A administrative extension

The above Phase 1 visitor architecture is preserved. `admin/` is a separate privileged Python package, with pinned administrative dependencies outside npm/Vite. SDK imports are lazy and limited to explicit remote commands. Security Rules deny all clients, while administrative identity is authorized through IAM. Production access and update flags are off by default. Historical setup and publication reports record earlier approved operations. This document describes the implemented architecture.

Canonical IDs use SHA-256 of `2026-11\0<exact code>`; the full import CLI creates pending/unverified primary records. The separately gated Quick Import path creates published/unverified records under `community-current-season-v1`. Immutable source sightings preserve evidence, and revision-checked review transactions or atomic Quick Import batches record audits. Import never changes existing code documents. Published-only data is validated and staged to a new private directory; explicit offline promotion retains prior assets/archive and atomically switches the manifest last. The current public release is identified by [the manifest](public/data/manifest.json). The loader now accepts real ISO observation dates rather than only the initial fixture date; source detail displays each record's date. Existing season/history keys remain stable.

Manual local CLI + reviewed publishing PR is the chosen no-cost publishing workflow. A read-only, secret-free GitHub Action validates PRs and runs demo emulator tests; it cannot import/publish. The full owner/IAM/operation budget and rollback contract is in `docs/PHASE2A_ADMIN.md`. `npm run snapshot` stages published Firestore data. `npm run snapshot:preview` regenerates only the original offline fixture into a separate staging directory. See [Quick Import](docs/QUICK_IMPORT.md) for routine updates and [season policy](docs/SEASONS.md) for future editions.
