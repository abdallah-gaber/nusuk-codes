# Nusuk Challenge Winners

## Source findings as of 25 November 2026

The archive contains 25 verified Umrah winners announced from November 1 through November 25. Each record links to the original Nusuk announcement and records the UTC verification time. The posters provide the published name, country flag, prize and **Winner No.** The post provides the announcement date. The winner number is stored as published, with the announcement date recorded independently. ## Reviewed updates

1. Open the official `@MyNusuk` announcement and read the original poster. For X, use the public post embed if the permalink is inaccessible. Compare the poster and post date against existing records before adding a row.
2. Edit [the winners JSON](../src/winners/data.json). Assign the next unused stable `id`. Copy the published `displayName` exactly. Set `prize` to `umrah`, keep `announcedOn` as the verified Saudi calendar date in `YYYY-MM-DD` or use `null`, and record the canonical `announcementUrl` and `verifiedAt` in UTC (`YYYY-MM-DDTHH:mm:ssZ`). Include `country` as ISO 3166-1 alpha-2 when the source provides a country or recognizable flag. Include `winnerOrdinal` only when the poster explicitly gives a winner number. Keep any missing optional fields absent and keep the record limited to these public details.
3. Set archive `updatedAt` to the UTC time of the reviewed change. Use `presentationEnabled: false` to hide the archive if its presentation needs to be suspended. The build requires valid reviewed records when presentation is enabled. The archive marks its coverage as potentially incomplete and flags when the latest dated announcement is over a week old.
4. Run `npm run validate:winners` and `npm run build`. Commit the JSON on a branch named `data/winners-YYYY-MM-DD` and open a PR listing the original announcement links. The owner reviews the JSON against the posters before deciding when to merge. The existing PR checks also validate the dataset. The Vercel configuration skips automatic deployment for these review branches.

## Validation and performance

- `npm run lint`, `npm run typecheck`, `npm run validate:winners`, `npm test` and `npm run build` passed. The full suite passed 176 tests, including 34 for the winners data.
- Headless Chrome passed 12 locale and viewport combinations. Arabic and Urdu rendered RTL, English and Indonesian rendered LTR, and the archive fit at 320, 390 and 1280 CSS pixels without horizontal overflow. All 25 winners appeared in reverse chronological order, with the Ramadan label on the five verified dates from November 21–25. The browser checks covered keyboard expand and collapse, manual rotation, pause on hover and focus, explicit pause and resume, reduced motion, silent automatic changes, and the stale archive state.
- The 320px expanded archive passed the scoped axe WCAG A/AA checks in all four languages. Manual advancement updates a polite live region while automatic rotation leaves it alone.
- Copy and Next kept the same positions, dimensions and hit targets as the baseline in all 12 combinations. The interaction check captured the clipboard write and confirmed progression to a different code. The enabled production build added 0.69 kB gzip to the entry JavaScript. The separate 5.34 kB gzip winners JS and CSS loaded after the code snapshot. The disabled build emitted no winners assets and made no winners requests.
